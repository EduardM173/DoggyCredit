# HU-08: preparación institucional

La ruta `/:tenantSlug` muestra los tres requisitos de preparación desde `GET /api/institution/tenants/:tenantSlug/home`. El backend calcula el progreso a partir de la confirmación institucional persistida, la habilitación de `BANK_MOCK` por tenant y al menos un producto seleccionado para personas. El slug es contexto de navegación; la sesión y la membresía activa autorizan el acceso.

La institución se confirma con `POST .../institution` (nombre y tipo; el NIT permanece inmutable), la fuente con `POST .../source` y los productos con `POST .../products` (`productIds`). Solo `INSTITUTION_ADMIN` puede modificar estos datos. Las operaciones son seguras ante reintentos y generan eventos de auditoría de negocio. Swagger expone los cuatro endpoints.

La migración `20261004090000_hu08_institution_preparation` añade las confirmaciones y el proveedor global `BANK_MOCK`. Aplicar con `npm run prisma:deploy` y regenerar el cliente con `npm run prisma:generate`.

Para una institución de demostración ya aprovisionada, el seed existente acepta `SEED_DEMO_PRODUCTS=true` y, opcionalmente, `SEED_DEMO_TENANT_SLUG=<slug>` antes de ejecutar `npm run prisma:seed`. Se restringe a `NODE_ENV=development|test`, crea los tres productos visibles en los mockups y no sobrescribe productos existentes ni sus selecciones. Las reglas financieras y umbrales de S2-RF-04 siguen pendientes; esta HU solo permite seleccionar productos, sin decidir recomendaciones.

La acción `Invitar analista` se muestra al completar 3/3 y queda deshabilitada hasta que exista la ruta funcional de Equipo/HU-09. No crea una invitación simulada.
