# HU-07: Inicio de sesión institucional

El portal `/iniciar-sesion` autentica la identidad global `User` con correo normalizado y la misma verificación Argon2id de HU-06, aplicando NFC a la contraseña. No solicita institución. Un usuario sin `TenantMembership ACTIVE` ve «No tienes acceso institucional activo»; uno con una membresía entra en `/{tenantSlug}`; con varias, `/elegir-institucion` muestra solo las activas. El selector es UX, nunca autorización. El enlace de destino se acepta únicamente si es un path interno de un slug actualmente autorizado; URLs externas, esquemas y rutas ajenas se descartan.

`POST /api/institution/auth/login` crea una `InstitutionSession` nueva con 32 bytes aleatorios, almacena solo SHA-256 del token y entrega cookie HttpOnly, SameSite=Strict y host-only. En producción la cookie `__Host-dc-institution-session` es Secure, Path=/; en desarrollo se usa `dc-institution-session`. No se mezcla con `AdminSession`. `GET /api/institution/auth/me` reconsulta las membresías activas; `POST /api/institution/auth/logout` revoca la sesión en PostgreSQL y borra la cookie. El timeout inactivo es 30 minutos y el absoluto 480 minutos por defecto, configurables con `INSTITUTION_SESSION_IDLE_MINUTES` e `INSTITUTION_SESSION_ABSOLUTE_MINUTES`. La actividad no alarga el límite absoluto. La validación y la revocación se comparten entre instancias mediante PostgreSQL.

`GET /api/institution/tenants/:tenantSlug/home` usa `InstitutionSessionGuard` y `TenantContextGuard`. Tras validar la sesión, el guard consulta `Tenant` y `TenantMembership ACTIVE` actuales para construir un `TenantContext` en el request; solo entonces el controller devuelve datos de Mockup 10. Sin sesión responde 401; sin membresía activa para un tenant existente, 403; slug inexistente, 404. `platformRole` no concede acceso. Revocar una membresía surte efecto en la siguiente petición. El backend ignora cualquier `tenantId` del navegador. El home sigue provisional: no hay clientes, evaluaciones, productos ni reportes de Sprint 2.

Las mutaciones usan Origin exacto y `X-DoggyCredit-Institution: 1`; CORS se limita al origen configurado y Helmet/no-store se conservan. El login usa límite local por IP y par IP-email hasheado, de alcance por proceso. Producción requiere HTTPS en el despliegue. `User` no tiene tenant fijo y el frontend no almacena secretos en Web Storage. La migración `20260927033000_hu07_institution_sessions` agrega la tabla de sesiones sin alterar cuentas o sesiones administrativas existentes.
