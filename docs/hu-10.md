# HU-10 - Preparar una nueva evaluacion crediticia

El analista utiliza el flujo institucional de Nueva evaluacion para identificar a una persona o empresa, reutilizar o crear su expediente dentro del tenant, indicar finalidad y monto, y registrar consentimiento. Se crea un caso `DRAFT` con snapshot del solicitante e idempotency key. La consulta de fuentes y las recomendaciones se realizan al procesar el caso; no forman parte del guardado inicial.

La implementacion de Sprint 3 amplia este mismo flujo para empresas, fuentes multiples, catalogo institucional e historial. Los endpoints vigentes estan en `apps/api/src/evaluations/evaluations.controller.ts`; el wizard esta en `apps/web/src/features/institution/EvaluationWizard.tsx`. No existe un segundo modulo de evaluacion paralelo.

La migracion `20261006000000_evaluation_preparation` agrega columnas opcionales al expediente y un fingerprint opcional sin modificar registros anteriores. El flujo consolidado usa el snapshot de la evaluacion como registro de los datos autorizados al momento de crearla.

En desarrollo o test puede ejecutarse `SEED_DEMO_EVALUATIONS=true npm run prisma:seed` para crear instituciones y analistas ficticios. El seed no crea evaluaciones ni resultados y no borra datos existentes. Tambien puede usarse `SEED_DEMO_PRODUCTS=true` para agregar productos demo a instituciones anteriores. Las instituciones nuevas reciben esos productos desactivados durante el aprovisionamiento en desarrollo.

Para verificar el recorrido, ejecutar las pruebas de API y web de Evaluations, ademas de las pruebas de aprovisionamiento y preparacion institucional. No se usa el antiguo endpoint alternativo `/evaluations/preparation` ni la pantalla `EvaluationPanel`.
